# Аудит исходного проекта

Проект уже покрывает основные сценарии семейного учёта: операции, два счёта, долги, кредиты, аналитику и экспорт. Главный недостаток исходной версии — недостоверное состояние кредитов и отсутствие видимой в файле серверной модели прав. Внешний вид был вторичным по отношению к этим проблемам.

| Приоритет | Проблема исходного файла | Что изменено |
|---|---|---|
| Критический | Остатки LOANS изменялись только в памяти и сбрасывались после обновления страницы | Отдельные документы `loans`; кредит и платёж записываются атомарно |
| Критический | Локальный долг уменьшался до успешного сохранения транзакции | Расчёт выполняется на копии внутри Firestore transaction; при ошибке нет частичного изменения |
| Критический | Любая введённая сумма списывала фиксированную разбивку | Ввод фактической разбивки; сумма равна телу + процентам + неустойке |
| Высокий | Администратор определялся по началу email, пароль удаления был в исходнике | Роли из подписанного токена Firebase; пароль удалён; подготовлены серверные правила |
| Высокий | Реальные суммы кредитов были доступны в исходном HTML без входа | Суммы вынесены в частный файл миграции; рабочая страница получает их после авторизации |
| Высокий | Досрочка свыше остатка полностью попадала в расходы | Превышение остатка отклоняется |
| Высокий | Редактирование или удаление платежа не восстанавливало кредит | Такие операции заблокированы; нужна специализированная отмена, которой пока нет |
| Высокий | Нулевая досрочка могла показывать экономию; часть расчётов бралась от сегодняшней даты | Единая модель графика с округлением до копеек, сравнением одинаковых моделей и датами от следующего платежа |
| Средний | Один фиксированный размер неустойки применялся ко всем кредитам | Прогноз не придумывает неустойку; реальные части вводятся по выписке |
| Средний | Ближайший платёж показывал один кредит при нескольких кредитах на одну дату | Суммируются платежи по всем кредитам с ближайшей датой |
| Средний | YTD сравнивался с меньшим периодом того же года | Сравнение с теми же месяцами прошлого года |
| Средний | Выбор кредита в калькуляторе сбрасывался при обновлениях | Выбранный кредит сохраняется |
| Средний | Двойное нажатие могло создать повторную операцию | Блокировка действий на время текущей записи |
| Средний | Идентификаторы транзакций подставлялись в inline JavaScript | Обработчик кликов по экранированным data-атрибутам |
| Средний | CSV допускал формулы из текстовых полей | Текстовые значения с опасными префиксами нейтрализуются |
| Средний | Ошибка была незаметна под открытой модалкой | Общие уведомления поверх модальных окон |
| Средний | Не было связей label/input и удержания фокуса в диалогах | Подписи, роли диалогов, фокус, Tab и возврат фокуса |
| Низкий | Полоски категорий использовали строчные span без display:block | Исправлено отображение ширины полос |

## Что нельзя установить по одному HTML

- Какие Firestore Security Rules сейчас опубликованы и кому они открывают доступ.
- Какие настоящие UID принадлежат Андрею и Лере.
- Актуальны ли встроенные остатки кредитов и на какую дату они подтверждены.
- Какие платежи уже были записаны в базе и как они соотносятся с выписками.
- На каком домене работает приложение и какие ограничения Auth настроены.

Поэтому версия подготовлена локально, без изменения рабочей базы и публикации. Называть её полностью готовой к эксплуатации до настройки и серверной проверки было бы неверно.

## Оставшиеся ограничения

1. Расчёты графика — ежемесячная аннуитетная модель, не точная банковская выписка. Ежедневное начисление, комиссии и банковские правила досрочки не моделируются.
2. График, срок и сумма будущего платежа после фактического внесения обновляются вручную через сверку. Это исключает выдуманные изменения договорных условий.
3. Полноценная отмена кредитного платежа, восстановление JSON и просмотр журнала сверок в интерфейсе пока отсутствуют.
4. Загружается вся история операций. Для больших объёмов нужна пагинация и серверные агрегаты. Для двух пользователей с небольшой историей текущая схема проще.
5. CDN-зависимости требуют сети. Сбой Chart.js не блокирует таблицы; без Firebase отображается сообщение о невозможности загрузки. Полноценного автономного режима нет.
6. Подготовленные Firestore rules ещё не проверены в эмуляторе. Тесты сохранения используют тестовый адаптер и не заменяют серверные проверки.
7. Существующий клиентский формат денежных сумм сохранён для совместимости. Новые расчёты округляются до копеек; отдельная миграция всех денежных полей на целые копейки не проводилась.

Рекомендуемое следующее действие — сверить исходные остатки и подключить новую версию к отдельному тестовому Firebase-проекту, проверить роли и операции, затем согласованно обновить рабочую версию.
