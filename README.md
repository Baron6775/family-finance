# Семейные финансы — результат доработки

Подготовлена исправленная версия исходного приложения. Исходный файл на рабочем столе не изменён. Рабочая база Firebase не изменялась. Эта версия требует настройки Firebase перед использованием с настоящими данными.

## Что открыть

- **preview.html** — интерактивная демонстрация с вымышленными операциями и одним тестовым кредитом. Для входа укажите любой email и любой текст вместо пароля. Настоящий пароль не нужен. Данные хранятся только в памяти и исчезают при перезагрузке. Подключения к Firebase нет; графики загружаются из CDN.
- **index.html** — рабочая версия с Firebase. Код и стили включены в один файл; рядом лежащий finance-core.js для работы страницы не требуется.
- **AUDIT.md** — найденные проблемы, исправления и ограничения.
- **firestore.rules** — подготовленные правила доступа. Перед применением обязательна проверка в Firebase Emulator: здесь правила ещё не исполнялись.
- **PRIVATE-loan-seed.json** — исходные кредитные данные, извлечённые из вашего HTML. Это личный файл для сверки и переноса; не размещайте его на сайте.
- **setup-firebase.cjs** — административный помощник для назначения ролей и переноса исходных остатков. По умолчанию только показывает действие.
- **finance-core.js**, **finance-core.test.cjs**, **persistence.test.cjs** — расчётное ядро и 21 регрессионный тест.

## Перед переходом на новую версию

1. Сохраните резервную копию текущей базы Firebase и оригинального HTML. Экспорт CSV не заменяет резервную копию всей базы.
2. Проверьте PRIVATE-loan-seed.json по актуальным выпискам. В старом приложении платежи не сохраняли остатки кредита, поэтому встроенные значения могут быть устаревшими. Автоматически восстанавливать их по описанию транзакций нельзя: у старых платежей нет надёжной связи с кредитом и разбивки.
3. В Firebase Authentication определите точные UID двух пользователей. Через доверенное административное окружение назначьте custom claim `familyRole`: `andrey` и `lera`. Префикс email больше не даёт права администратора. После назначения нужно выйти и войти снова.
4. В Firebase Emulator проверьте правила: отказ без входа; отказ пользователю без роли; чтение обеими ролями; создание и изменение обычных операций; удаление только Андреем; запрет изменения и удаления кредитных платежей; атомарная запись платежа вместе с кредитом; запрет одиночного изменения кредита Лерой; сверка Андреем; отказ отрицательным и некорректным суммам. Затем примените проверенные правила к проекту.
5. Перенесите сверенные остатки в `loans` административным помощником либо через «Настроить остатки» в приложении. Укажите действительную дату сверки. Не импортируйте старые встроенные остатки вслепую.
6. Разместите **только index.html** на вашем HTTPS-хостинге. Добавьте домен в разрешённые домены Firebase Authentication, если это необходимо. Вся папка outputs не является каталогом для публикации.
7. Проверьте на тестовом проекте: вход двух пользователей, сохранение после перезагрузки, одновременный платёж с двух устройств, ошибку сети, экспорт, мобильный экран. После этого переходите на настоящую базу.

Для помощника необходимы Node.js, установленный официальный пакет `firebase-admin` и Application Default Credentials с административными правами на проект `family-finance-72604`. Учётные данные не должны находиться в HTML или публикуемой папке.

Пример проверки будущего действия:

```powershell
node setup-firebase.cjs role --uid YOUR_ANDREY_UID --role andrey
node setup-firebase.cjs role --uid YOUR_LERA_UID --role lera
node setup-firebase.cjs seed --date YYYY-MM-DD
```

Замените UID и дату реальными значениями. Для выполнения проверенного действия добавьте `--apply`. Импорт прекращается без изменений, если хотя бы один кредит уже существует. Помощник не изменяет старые операции.

## Как работает учёт

Начальный остаток счёта — база, к которой прибавляются поступления и из которой вычитаются списания. Это не установка текущего баланса. Поступления и списания включают займы, возвраты долгов и платежи по кредитам: показатели описывают движение денег, а не бухгалтерскую прибыль.

Задавать начальные остатки обоих счетов может только Андрей. У Леруськи поля ввода и кнопки «Задать» скрыты; просмотр балансов доступен. Ограничение также проверяется обработчиком записи и правилами `accounts/main`. Для серверной защиты обновлённые правила необходимо применить в Firebase.

Переводы между счетами доступны обоим участникам в отдельном разделе. Выберите направление, дату и сумму. Один документ операции `transfer` содержит отправителя `owner` и получателя `recipient`: он одновременно уменьшает один баланс и увеличивает другой, не затрагивая начальные остатки, доходы и расходы семьи. Перевод виден в журнале при фильтре любого участника, попадает в CSV и JSON. Редактирование перевода запрещено; Андрей может удалить ошибочный перевод (оба баланса восстановятся) и создать правильный. Это учёт уже совершённого перевода, без подключения к банку; отрицательные остатки допускаются, как и для других операций.

Фактический платёж по кредиту вводится по разбивке выписки: тело, проценты, неустойка. Общая сумма рассчитывается автоматически. Платёж и остаток кредита сохраняются одной транзакцией Firestore. До подтверждения сервера локальный остаток не меняется.

Дата следующего платежа, окончание кредита и новый ежемесячный платёж не выводятся из факта произвольного перевода. Их обновляют через сверку по информации банка. Досрочный платёж уменьшает фактически погашенную часть долга; модель экономии не переписывает банковские условия.

Сверка изменяет остатки и записывает историю в `loanReconciliations`, но не создаёт денежное списание. Корректировать ошибочную кредитную операцию обычным редактором нельзя — полноценная отмена с восстановлением истории ещё не реализована.

Резервная копия JSON включает загруженные операции, счета и кредиты. Это выгрузка текущих данных, а не полный экспорт Firebase: журнал сверок и Auth в неё не входят. Автоматический импорт JSON в этой версии отсутствует.

## Проверки

```powershell
node --test finance-core.test.cjs persistence.test.cjs account-permissions.test.cjs transfers.test.cjs
```

Результат: **21 из 21 теста прошли**. Проверены суммы, календарные даты, нулевая ставка, досрочное погашение, согласованность разбивки, отсутствие изменений при ошибке записи и две последовательные конкурентные попытки платежа на тестовом адаптере.

В браузере проверены вход в тестовом режиме, добавление операции с копейками, поиск, сверка и сохранение кредитного платежа. Выполнен визуальный просмотр на ширине 390 px. Проверка реального Firebase, правил в эмуляторе и перезагрузки с серверными данными пока не проводилась.

Официальные основания решений: [атомарные операции Firestore](https://firebase.google.com/docs/firestore/manage-data/transactions), [проверка доступа правилами](https://firebase.google.com/docs/firestore/security/rules-conditions), [защита полей документов](https://firebase.google.com/docs/firestore/security/rules-fields).
